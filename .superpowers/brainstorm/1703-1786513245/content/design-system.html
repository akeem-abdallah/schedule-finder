Grid changes: the day header becomes a tinted band, hour lines are visible but faint, the time gutter is small muted text, and the whole grid gets a rounded border so it reads as one object. Blocks use the tinted + left-border treatment you picked.

Three judgment calls I made — reverse any of them

1. Keep <select> native, style only the closed state. Styling the closed box (border, radius, padding, custom arrow via appearance: none) is ~6 lines. Styling the open dropdown list is impossible in CSS — it needs a custom JS component, and on a phone that's strictly worse, because native selects open the OS picker which is far better than anything hand-rolled. With ~700 rows and a long subject list, that native picker is an asset.

2. The weekly grid scrolls horizontally on a phone. 5 days × 140px + a time gutter is ~810px; a phone is 375px. The alternatives are shrinking columns to ~60px (can't fit "CSCI 104-01") or hiding days (destroys the point). Horizontal scroll inside a rounded container, with the time gutter stuck to the left, is what real timetable apps do. This one has actual layout work behind it — worth its own task.

3. Labels move above fields instead of beside them. This is what makes mobile free: the desktop and mobile layouts become the same structure, just one flexing and one stacking — no orphaned "Code:" label, and the media query gets simpler rather than more complicated.

If this is right, the build order is: tokens & page frame → controls (buttons, selects, focus, error) → view 1 layout → view 2 cards → grid → mobile grid scroll. Each is a separate task with a real finish line, which is what stops a design pass from sprawling.
