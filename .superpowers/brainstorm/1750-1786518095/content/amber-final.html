Complete reference. Every value you need is here; nothing should require asking. 12-hour times, no centered heading, zero radius anywhere.

7 — States & the eight course hues

Focus — outline: none plus box-shadow: 0 0 0 3px var(--focus), on every select, button and checkbox. Nothing in the app currently shows focus at all; this is accessibility, not polish.
Hover — primary button → --accent-hover; secondary → border goes --rule-strong; × → text goes --danger, no background change.
Disabled — prev/next at the ends of the result list: --faint text, --rule border, cursor: default. Don't hide them, the layout would jump.
Row hover — background --surface-alt. That's the whole effect.

The eight hues, one hex each. Wash is the hue at 10% on light, 24% on dark; left rule is the hue at full; block text always uses --text / --muted. One value covers both themes — that's the whole reason dark mode is cheap here.

#2f6bff#e0561f#17a06a#9d4edd#c9910d#00a0b8#e0447f#7cb518

Your SECTION_COLORS has six and cycles with %, so a 7-course shortlist repeats a color. Eight covers a realistic maximum.

8 — Build order

1. Tokens + page frame. Both :root blocks, body, the board container, the status strip. Replaces the <h1>.
2. Buttons, selects, focus, error. Pure CSS, no JSX. Biggest visible jump for the least work.
3. View 1 → table. JSX: the row grid, column header, mobile collapse.
4. View 2 → section rows. JSX: meeting days/times per section.
5. Grid restyle. Day header band, gutter, rules, blocks.
6. Grid horizontal scroll + sticky gutter. Its own task — real layout work.
7. Theme toggle. Only if you want it; the dark values already exist so it's a button plus localStorage.

On custom properties. plan.md says extract them as a refactor once repetition is visible, not upfront — and the reason given was "naming colors before choosing them is backwards." That reason is now satisfied: the colors are chosen. Two themes also make variables structural rather than cosmetic — you cannot swap a theme without them. So starting with the token block here isn't jumping the gun; it's the refactor arriving exactly when its precondition was met.
